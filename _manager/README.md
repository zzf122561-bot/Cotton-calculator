# CottonCal 管理员工作台

本目录归管理员会话 01a0b4f7-a6f2-7d83-a4d5-e4de2fd6999c 维护。项目仍是根目录的单一 Git 仓库，这里不是嵌套仓库。两个功能会话按 PROJECT.md 和各自 AGENTS.md 工作。规则是流程约束，不能阻止同一 Windows 用户越权写文件；管理员每次集成前审查路径和 Git 状态。

## 目录

- THREADS.md：会话登记、消息和回执状态。
- HANDOFF_TEMPLATE.md：功能会话主动汇报格式。
- RELEASES.md：候选与正式版本索引、验收边界。
- RELEASE_MANIFEST_TEMPLATE.md：每个测试或正式版本的独立记录字段。
- releases/：全部历史 APK、网页 ZIP、原交接资料及以后不可覆盖的版本包。APK/ZIP 与截图只在本地保存，GitHub没有这些二进制的备份。
- templates/web/：管理员控制的电脑端服务器交接模板。
- legacy/web/：仅供追溯的旧手机说明和双包脚本，不是新版本入口。
- scripts/build-desktop-web.ps1：新电脑端网页包入口。

## 每次交接和发版

1. 核对会话登记、用户指令、工作区与远端状态；只收取对应功能路径的变更。收到消息不等于技术测试通过。
2. 管理员按功能路径审查并提交到本地 integration，记录精确提交、测试结果、文件名/大小/SHA-256、浏览器或设备证据和未解决事项。测试包写入独立目录，不覆盖旧包。
3. 用户验收测试包后，才将对应提交纳入 main；核对正式包对应的功能源码及构建配置与已验收候选一致，打 android-vX.Y.Z 或 web-vX.Y.Z 标签，普通非强制推送并对照远端完整 SHA。未验收候选不推入远端 main。
4. 自动化、设备/浏览器和用户验收分开记录。无设备时不称设备测试通过；未部署时不称线上验收完成。任何远端非快进或来源不明的差异都停止，不强推。

每个版本使用 RELEASE_MANIFEST_TEMPLATE.md 单独记录；脚本生成的 MANIFEST.json 仅证明打包信息，不能替代技术测试、设备/浏览器或用户验收记录。

现有功能会话共用根目录；管理员另用 _manager/.worktrees/main/ 作为本地 main 工作树，根目录保持 integration。该工作树和临时打包目录均被忽略。签名与本机配置保持项目原位置，不复制到 Git；正式 Android 包由管理员在原构建环境完成签名和校验。若多个候选并行，只有相关代码路径和必要构建配置全部与已验收测试包匹配时才可升级为正式包。
